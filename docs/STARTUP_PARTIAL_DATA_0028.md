# 0028: неполные данные при старте

В полном safe-mode тесте0027 CORE прошёл за~2s, но data_wait завершился
`data_missing_field`, childexit0. Конкретный ответ не сохранён; неизвестно,
какого поля не хватило и присутствовал ли WAIT. NUT2.8.5 может публиковать
начальный `ups.status: WAIT` до окончания DUMPALL (server/sstate.c), поэтому
успешный запрос upsc сам по себе не доказывает полноту данных.

0028 повторяет корректно оформленный неполный ответ только внутри START,
в существующем data readiness окне20s. Отсутствие полей никогда не означает
готовность. Требуются полные данные и правильная идентичность обоих endpoint.
Все присутствующие identityполя проверяются до решения о повторе; неверное
значение, дублирование, синтаксическая ошибка, противоречие OL+OB и неизвестные
transport/permission ошибки остаются фатальными. Обычный HEALTH при неполноте
остаётсяrc2 и ничего сам не останавливает.

Для startup missing возвращается существующий внутренний rc3 (ещё не готов).
Постоянная неполнота исчерпывает20s и приводит к unwind сrc1, не кUSBabsence75.
Если отдельно наблюдались Data stale/Driver not connected, их прежняя семантика
сохраняется. CORE20s/data20s, executor limits, units, USB/lifecycle и DSMtimer5min
не изменены. Нет дополнительных sleeps вне существующего опроса и новых служб.

В runtime NUT_START_DIAG добавлено числовое поле `missing_mask`; битовые значения:

| Бит | Поле |
|---|---|
| 1 | driver.name |
| 2 | device.mfr |
| 4 | device.model |
| 8 | ups.vendorid |
| 16 | ups.productid |
| 32 | ups.status |

Маска — сумма отсутствующих полей;31 значит нет пяти identityполей,32 — нет
статуса. Для остальных диагностических событий0. Значения полей, rawответ,
серийные номера и секреты не записываются. Диагностика внеSTART остаётся тихой.

Проверки используют настоящий C-runtime с подменой только внешних операций
и времени. Это локальная проверка исправления; сама по себе она не доказывает успешный
автозапуск NAS. 23.10.2026 отдельно прошли upgrade и полный автоматический
safe-mode цикл 0028: [отчёт](SAFE_MODE_0028.md). В этом live-запуске
missing_mask=0; ветвь неполных полей не понадобилась. Финализация использует
тот же SPK без пересборки и повторных тестов.
