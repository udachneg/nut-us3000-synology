# 0027: увеличенное окно CORE

Относительно диагностической0026 единственное изменение поведения — окно
повторных CORE-проверок после запуска пары увеличено с3000 до20000мс.
Пакет продолжает запуск сразу после успеха; фиксированной задержки20с нет.
Дедлайны отдельных команд не изменены: окно не является жёстким потолком
полного времени участка, и текущая успешная проверка принимается до проверки
дедлайна. Отдельный бюджет готовности данных UPS остаётся20000мс и начинается
после CORE, а не вместе с ним. Все проверки identity и unwind прежние.

Формат и места диагностических сообщений из [0026](STARTUP_DIAGNOSTICS_0026.md)
сохранены. В историческом документе указан прежний CORE3000мс; для0027 действует
20000мс. При устойчивой ошибке CORE остаются rc1, остановка только собственной
пары и проверка quiescence; увеличение окна не превращает ошибку в успех.

Изменение даёт запас при загрузке, но не является доказанным исправлением
исторического отказа. Успешный cold start0026 не воспроизвёл прежнюю ошибку.
Новые адресные проверки моделируют переходы за3,31с и18,16с, исчерпание окна,
ранний успех, сохранение диагностики/отказов и отдельный бюджет данных.
Реальный safe-mode → возврат питания → reboot → автозапуск0027 ещё не выполнен.

Версия внутри SPK сразу2.8.5-0027, без rc в имени бинарного артефакта.
При успешных согласованных испытаниях тот же файл с тем же SHA256 можно
обозначить финальным изменением заголовка/notes/prerelease релиза GitHub.
Предпочтительно изначально использовать tag v2.8.5-0027, а кандидатность
обозначить prerelease и заголовком. Менять tag или пересобирать SPK для этого
не нужно. Любая правка бинарника после тестов — уже другой проверяемый артефакт.
Этот документ не публикует релиз и не разрешает установку или отключение питания.
